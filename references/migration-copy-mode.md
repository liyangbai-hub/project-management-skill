# 模式二：独立标准化副本规范

本规范用于只读理解既有项目，并在独立目标路径创建可运行、可验证、可接力的标准化副本。模式二的产物是新副本以及可复核的复制证据，不是对源项目的改造。

## 一、不可突破的边界

- **源项目只读。** 全程不得写入、移动、重命名、覆盖、删减源项目中的文件、目录、配置、版本历史或元数据，也不得在源目录内生成扫描报告、缓存、锁文件、测试输出或事实层。
- 只读分析命令也必须避免会自动格式化、安装依赖、升级锁文件、生成缓存或执行初始化脚本的选项。不能确认命令是否只读时，不在源项目运行。
- 严禁原地迁移。源目录不能兼任目标目录，也不能通过先改名再补文件、在源目录套一层新目录或其他等价方式完成模式二。
- **源路径与目标路径不同**，且两者必须在路径解析后保持隔离。
- **目标不位于源目录内部**，源目录也不得位于目标目录内部。
- 非空目标默认停止；删除、覆盖或合并已有内容都不是默认行为。
- 凭据、令牌、私钥、真实环境变量值和个人隐私数据默认不进入目标。
- 不自动执行 `git init`、commit、创建远程仓库、push、修改远程分支、PR、Release 或其他网络、远程操作。

若任一边界无法证明满足，应在复制开始前停止，报告已确认事实、未知项和所需授权，不得以“尽量小心”代替隔离证明。

## 二、完整阶段流程

严格按以下顺序执行：

1. **确认参数**：确认源目录、目标目录、新项目名称、目标用途、Git 历史策略、大型资产策略、可重建产物策略和敏感内容策略。
2. **路径隔离检查**：比较解析后的规范化绝对路径，检查包含关系、符号链接和联接点，并检查目标是否非空。
3. **复制前快照**：在源目录外记录源项目清单、大小、内容哈希和适用时的 Git 状态。
4. **只读理解**：阅读实际代码、配置、依赖、文档和历史，确定项目用途、运行方式、关键链路、现状和不可替代内容。
5. **制定复制计划**：将每类内容明确归入直接复制、目标重新生成、选择性复制、默认排除或敏感内容。
6. **创建副本**：只在独立目标路径写入；保持原生工具链布局，并按 `project-templates.md` 建立有实际内容的目标事实层。
7. **验证目标**：核对关键文件，运行适用的启动、构建和测试，扫描源绝对路径残留与敏感内容。
8. **证明源未变**：重复源项目快照，用清单、大小、内容哈希和适用时的 Git 状态进行前后比较。
9. **交付报告**：报告复制范围、排除项、验证状态、源未变证据、失败或限制以及未执行操作。

任何阶段失败时都转入“失败和中止处理”，不得跳过失败继续宣称副本完成。

## 三、确认参数与授权契约

复制前至少明确以下内容：

| 参数 | 必须记录的决策 |
|---|---|
| 源目录 | 用户指定路径及解析后的规范化绝对路径 |
| 目标目录 | 用户指定路径及解析后的规范化绝对路径 |
| 新项目名称 | 目标事实层和必要配置中使用的名称 |
| 目标用途 | 继续开发、归档、交接、精简演示或其他用途 |
| Git 历史 | 不复制、完整保留或经明确范围选择性保留 |
| 大型资产 | 复制、外置并记录获取方式、以占位说明替代或排除 |
| 可重建产物 | 排除并记录重建命令，或因交付要求明确保留 |
| 敏感内容 | 排除、脱敏替代、生成示例文件；不得记录真实敏感值 |
| 目标已有内容 | 必须为空；非空时停止并取得具体策略授权 |
| 验证方式 | 关键文件、启动、构建、测试、路径和敏感扫描的适用项 |

用户尚未决定的事项不得擅自选用破坏性策略。Git 历史、大型资产或敏感内容存在歧义时，先列出候选范围、代价和风险，再请求用户选择。

## 四、路径隔离与目标状态检查

### 4.1 比较规范化绝对路径

路径检查不能只比较用户输入的字符串。复制前应使用当前平台可用的方法完成：

1. 将源和目标转换为绝对路径；
2. 规范化 `.`、`..`、重复分隔符、盘符和平台适用的大小写语义；
3. 对已存在的路径解析符号链接、目录符号链接和 Windows 联接点等重解析点；
4. 对尚不存在的目标，解析其最近已存在父目录，再组合剩余路径段；
5. 使用路径组件边界判断包含关系，不能用简单字符串前缀判断；
6. 在平台大小写不敏感时按该语义比较。

必须在任何复制或目标初始化前拒绝以下关系：

- 解析后的源与目标相同；
- 目标位于源目录内；
- 源位于目标目录内；
- 目标本身或其已有父路径通过符号链接、联接点或其他重解析机制指向源目录；
- 目标中的既有链接可能使写入回流到源目录；
- 无法可靠解析路径关系或没有权限检查关键路径组件。

符号链接和联接点既可能出现在源内，也可能出现在目标父路径中。复制工具“跟随链接”可能把源外内容带入目标，目标中的链接也可能把后续写入导回源项目。复制计划必须逐项决定链接是保留为链接、复制链接指向内容、替换为普通文件还是排除；无法证明安全时默认排除并报告。

### 4.2 非空目标

**非空目标默认停止。** 仅“目标目录已存在”不一定构成非空；应检查其中是否有文件、子目录、隐藏项、系统项或重解析点。

继续使用非空目标前，用户必须明确批准一种针对具体路径和冲突类型的策略：

- **仅补充合并**：只创建不存在的路径；任何同名文件或目录冲突都停止，不改动既有内容。
- **逐项冲突决策**：先生成冲突清单，再由用户明确指定每个或每一类冲突采用保留目标、采用副本或重命名落位。
- **受限覆盖**：只覆盖用户点名的确切相对路径；其他冲突停止。执行前必须备份被覆盖的目标内容并记录恢复位置。
- **完整替换**：属于删除或覆盖既有目标内容的高风险操作，必须对目标范围、备份方式和恢复方案取得单独明确授权。

“合并一下”“直接处理”“覆盖需要的”不算具体策略。授权必须能回答允许影响哪些目标路径、冲突如何解决、是否备份及失败如何回滚。无论采用何种策略，都不得扩大为对源项目的写操作。

## 五、复制前源项目快照

快照必须保存在源目录之外，且不得为了生成证据更改源文件。至少记录：

- 快照时间和所用方法；
- 相对文件与目录清单，包括隐藏项；
- 每个普通文件的相对路径和字节大小；
- 每个普通文件的内容哈希，推荐 SHA-256 或当前环境可用的等强度内容哈希；
- 符号链接、联接点等特殊条目的相对路径、类型和目标；
- 无法读取或无法计算哈希的条目及原因；
- 若源是 Git 工作树，记录操作前 Git 状态，包括未跟踪文件；必要时记录当前 HEAD 仅用于定位，不作修改；
- 源目录外观测到的权限或平台限制。

应使用稳定的相对路径和确定性排序，使前后快照可直接比较。文件修改时间（mtime）可以记录为异常线索，但复制、杀毒软件、索引服务和文件系统精度都可能影响它，因此 mtime 仅辅助，不能单独证明内容未变。

如果有文件无法读取、哈希或枚举，源未变证明会存在缺口。必须在复制前说明缺口并决定停止或经用户接受限制后继续；交付时不得把不完整证据描述为完整证明。

## 六、只读理解要求

模式二的核心不是机械复制，而是先建立足以指导副本取舍的真实理解。至少核验：

- 项目解决的问题、目标用户、典型输入与输出；
- 实际入口、主流程、模块边界、数据与状态流；
- 语言、框架、依赖管理、构建系统和原生目录约束；
- 启动、构建、测试、打包或适用于非代码项目的验证方法；
- 必需配置、外部服务、数据文件和运行环境；
- 当前完成度、半成品、占位实现、已知限制和关键 TODO；
- 不可替代的输入、生成但需交付的产物、大型资产及其来源；
- 现有文档与实际实现是否一致；
- 存在 Git 时与迁移决策相关的历史、分支或子模块事实。

文档只能作为线索。入口、依赖、命令、配置和完成度应通过实际文件核验。只读理解可以阅读 Git 历史和状态，但不得 checkout、reset、clean、更新子模块、安装钩子或执行会改变工作树的命令。

对可能产生写入的启动、构建或测试命令，源目录只记录其预期方式，不直接运行；应在目标副本中运行。若只有运行才能理解且无法保证只读，应先说明限制，不能用潜在写入换取理解。

## 七、五类复制计划

复制前建立逐目录或逐类清单，每项必须有分类、理由、目标位置和验证方式。

### 7.1 直接复制

适用于需要原样保留且不包含敏感值的内容，例如：

- 源码、测试和必要脚本；
- 依赖清单、锁文件和工具链配置；
- 不含秘密的静态资源和不可替代输入；
- 许可、已有设计文档和项目所需说明；
- 经核验属于项目真实交付物的文件。

直接复制保持相对路径、文件内容以及运行所需的大小写。权限位或可执行位若是运行条件，应在目标验证；不要为追求元数据完全一致而写回源项目。

### 7.2 目标重新生成

只在目标中根据目标事实重新创建，不从源机械照搬：

- `AGENTS.md`、`CLAUDE.md`、`README.md`、`DEVLOG.md`、`CHANGELOG.md` 等目标事实层；
- 根据目标名称或路径需要变化的配置；
- 从模板生成的无秘密示例配置；
- 明确可由确定性命令重建、且重建比复制更可靠的内容。

重新生成必须基于只读理解得到的事实，不得填充未经核验的能力或状态。已有同名项目文档若含有历史或业务信息，应先归入直接或选择性复制并吸收，不能用空模板覆盖其价值。

### 7.3 选择性复制

适用于只需部分内容或需按目标用途裁剪的集合，例如：

- 样例数据、历史文档、测试夹具、媒体资产；
- 多环境配置中的非敏感公共部分；
- 只与目标范围相关的插件、模块或子项目；
- 经用户明确选择的 Git 历史或大型资产。

必须列出纳入和未纳入边界，避免用“相关文件”等不可复核表述。选择性复制不得破坏被纳入部分的依赖闭包；若无法保持可运行，应调整范围或如实记录目标用途不是可运行副本。

### 7.4 默认排除

以下是候选排除项，不是脱离项目事实的绝对黑名单：

```text
.git/
node_modules/
.venv/
venv/
__pycache__/
dist/
build/
coverage/
.cache/
.tmp/
.DS_Store
Thumbs.db
日志、临时文件、编辑器缓存、下载缓存、测试输出、可重建的大型产物
```

排除前要确认其中没有不可替代输入、法律要求保留的记录或真实交付物。排除依赖与构建产物时，应在交付报告中写明恢复或重建命令；命令未实际验证时标记“未执行”或“结果不确定”。

### 7.5 敏感内容

敏感内容至少分为：

- **认证秘密**：密码、API 密钥、访问令牌、会话、私钥、证书私钥、云凭据；
- **真实环境配置**：含实际主机、账户、内部端点或秘密值的 `.env`、配置覆盖和部署文件；
- **个人与受保护数据**：姓名、联系方式、证件、账户、交易、医疗、位置等隐私或受监管数据；
- **组织机密**：未公开业务资料、客户清单、内部拓扑、商业合同、专有数据集；
- **可能泄密的派生物**：日志、崩溃转储、数据库快照、导出表、截图、录屏、缓存和模型输出。

默认处理是排除，并记录相对路径或类别而不输出真实值。目标确需配置结构时，创建不含真实值的 `.env.example` 或占位配置，并明确填写方式。脱敏副本必须验证真实值不可恢复；简单遮住部分字符可能仍可识别，不足以构成安全脱敏。

发现疑似秘密时停止该项复制和输出扩散。若秘密已经进入目标，立即停止后续操作，隔离目标，记录受影响范围并请求用户决定安全清理和凭据轮换；不得把删除目标文件描述为已经消除所有暴露风险。

## 八、Git 历史、大型资产与可重建产物

### 8.1 Git 历史

Git 历史策略必须在复制前确定：

- **默认不复制 `.git/`**：目标是内容副本而非历史克隆；报告源提交定位信息时只记录必要标识。
- **完整保留**：仅在用户明确要求、已评估历史敏感信息和体积、并能保证目标独立时采用。复制历史不等于获准创建远程或 push。
- **选择性保留**：若需筛选历史、子目录或分支，先说明这可能改写目标历史且需要专门工具和验证；没有清晰方案和授权则停止，不临时即兴操作。

无论哪种策略，都不在源仓库执行会改变工作树、索引、引用、配置、钩子或对象数据库的操作。目标是否初始化新仓库也必须由用户请求或明确授权决定，本规范不自动执行。

### 8.2 大型资产

大型资产按“是否不可替代、是否运行必需、是否允许复制、目标介质容量、版权与隐私”判断：

- 不可替代且获准复制：核对大小与内容哈希，目标验证可读取；
- 可从可信来源重新获取：可排除，但记录来源、版本、校验值和恢复步骤；
- 受许可、隐私或合同限制：默认排除并说明限制，不在报告中泄露内容；
- 目标只需示例：使用无敏感信息的小型替代物，并明确它不是完整资产。

不得仅因文件大就排除，也不得仅因项目依赖就默认复制。

### 8.3 可重建产物

构建输出、依赖目录、缓存和生成文件通常优先排除，并在目标通过原生命令重新生成。例外包括离线交付必须包含、生成工具已失效、产物本身是正式交付物或重建不可复现的情况。决定保留时记录原因、来源和验证；决定排除时记录准确重建步骤及其验证状态。

## 九、创建目标副本与事实层

只在路径检查、源快照和复制计划完成后创建目标。创建过程应：

1. 按批准的清单复制内容，不扩大范围；
2. 保留项目原生源码、测试、配置和资产布局，不强制创建统一源码目录；
3. 不把源目录的机器绝对路径写入目标配置或文档；
4. 按 `references/project-templates.md` 在目标建立有实际内容的事实层；
5. 事实层说明这是独立标准化副本、其来源范围、复制日期、关键取舍和验证状态，但不写入源机器敏感信息；
6. README 反映目标当前事实：用途、能力、架构、关键文件、环境、运行方法、限制和路线；
7. DEVLOG 建立首个真实工作单元，记录副本创建计划与结果、复制分类、验证和遗留项；
8. 只有目标中已落地且对其用户可见的变化才进入目标 CHANGELOG；
9. 有输入材料时建立 `requirements/INDEX.md`，不因复制而改名或修改原材料；
10. 不虚构源项目历史、目标测试通过状态或 Git commit。

如果目标事实层文件与待复制的源文档同名，应先保全源文档的有效信息，再通过明确合并方案生成目标当前地图；禁止静默覆盖。

## 十、副本验证

每项结果必须标记为“通过、失败、未执行、环境受限或结果不确定”，并记录方法与关键证据。

### 10.1 关键文件与结构

- 对照复制计划确认所有纳入项存在、所有排除项未进入；
- 核对入口、源码、依赖清单、锁文件、必要配置、测试和不可替代资产；
- 比较直接复制文件的大小与内容哈希；
- 检查大小写、可执行权限、链接处理和平台相关文件名；
- 确认目标事实层存在且内容来自实际理解，不是空模板。

### 10.2 启动、构建和测试

优先使用项目原生命令，在目标目录执行适用的依赖恢复、启动、构建、测试或文档验证。记录：

- 精确命令或人工步骤；
- 运行目录和必要环境，但不记录秘密值；
- 状态和关键输出摘要；
- 跳过的命令及原因；
- 失败是否由副本缺失、环境限制或源项目既有问题导致；证据不足时写“结果不确定”。

安装依赖、生成缓存和构建产物只能发生在目标或目标外的隔离环境，不能回写源项目。需要网络时必须遵守当前任务授权；无网络授权则标记未执行，不擅自联网。

### 10.3 绝对路径残留

扫描目标中的文本、配置、脚本和适用的元数据，至少检查：

- 指向源目录的完整绝对路径；
- 源机器用户目录、盘符或挂载点；
- 文件 URI、工作区配置、IDE 配置和构建缓存中的源路径；
- 符号链接或联接点仍指向源目录；
- 报告和事实层是否意外记录作者机器绝对路径。

二进制文件无法可靠扫描时，应记录范围和限制。发现源路径残留后，判断其是运行依赖、无害历史文本还是敏感暴露；修复只能发生在目标。

### 10.4 敏感内容检查

结合文件名、配置结构、秘密模式和人工语义检查：

- 真实 `.env`、私钥、令牌、密码和云凭据；
- 数据库、日志、转储、导出和个人数据；
- Git 历史中可能存在的秘密（仅当复制了历史）；
- 示例文件是否只含明确占位值；
- 报告是否泄露了扫描命中的真实值。

扫描工具未命中不等于不存在敏感信息，必须结合项目上下文。报告只记录类别、相对位置和处理，不回显秘密。

## 十一、源项目未变证明

目标验证后，以与复制前一致的方法重新生成源快照并比较：

1. 前后相对文件和目录清单完全一致，证明没有新增、缺失或改名条目；
2. 每个普通文件的字节大小一致；
3. 每个可读取普通文件的内容哈希一致；
4. 特殊条目的类型和链接目标一致；
5. 源为 Git 工作树时，前后 Git 状态一致，包括未跟踪文件；
6. 单独检查源目录是否出现本次工具可能生成的报告、缓存、锁文件、构建输出或临时文件；
7. mtime 只报告为辅助异常信号，不因 mtime 相同就推断内容相同，也不因 mtime 变化就忽略哈希证据。

判断规则：

- 清单、大小、哈希和适用时 Git 状态均一致，且无不可读缺口：可报告“源项目未检测到变化”。
- 存在不可读、未哈希或未枚举部分：只能报告“已检查范围内未检测到变化”，列出证据缺口。
- 任一清单、大小、哈希、链接目标或 Git 状态出现非预期差异：立即判定源不变验证失败，停止交付完成声明并进入异常处理。

不得以复制工具返回成功、没有故意写源、Git 状态干净或修改时间未变替代上述证据。

## 十二、失败、中止与恢复

### 12.1 复制前失败

路径不安全、参数不清、目标非空未授权、源快照不完整或发现敏感风险时：

- 不创建目标内容；
- 不改变源项目；
- 报告停止阶段、原因、现有证据和继续所需的具体决策。

### 12.2 复制中失败

- 立即停止新增写入；
- 保持源项目只读并先执行源未变检查；
- 记录目标中已创建、未创建和状态不确定的路径；
- 不自动删除部分目标，因为删除同样需要确认范围；
- 若目标是本次新建且用户已预先授权失败清理，可仅清理已记录的本次目标内容；否则请求用户决定保留用于诊断、移动隔离或删除；
- 恢复或重试必须从重新检查目标状态、路径隔离和快照开始，不能假设半成品可安全续写。

### 12.3 验证失败

目标启动、构建、测试、路径扫描或敏感检查失败时：

- 不把副本标为验证通过；
- 区分副本缺陷、源项目既有问题、环境受限和证据不足；
- 修复仅作用于目标，并记录变更与复验；
- 涉及扩大复制范围、引入敏感内容或覆盖目标既有内容时重新取得授权。

### 12.4 源不变验证失败

发现源项目出现任何非预期变化时：

- 立即停止目标后续操作和完成声明；
- 保全前后快照、差异清单和相关命令记录，避免继续污染证据；
- 不擅自“修回去”，因为恢复动作本身可能覆盖用户同时发生的修改；
- 向用户报告具体相对路径、差异类型和时间范围，请用户决定恢复、保留或进一步调查；
- 在用户确认前不得重试模式二。

### 12.5 用户中止

收到中止指令后停止在安全边界处，报告已经发生的目标写入和尚未执行的步骤。除非用户明确要求并授权，不清理目标、不更改源、不执行 Git 或远程操作。

## 十三、交付报告内容

交付报告可作为会话回复或写入目标的复制报告。写入目标时使用相对路径和占位路径，不记录源机器绝对路径或敏感值。结构可按项目习惯组织，但必须回答以下每一项：

1. **基本信息**：源项目、目标副本、新项目名称、执行范围，以及明确未执行的操作（Git 初始化、commit、网络访问、远程操作等）。
2. **参数与策略**：Git 历史、大型资产、可重建产物、敏感内容策略；目标初始状态为空或非空，非空时说明获得的具体授权、涉及路径和冲突处理方式。
3. **路径安全**：规范化路径比较结论；源与目标不同、目标不在源内、源不在目标内；符号链接、联接点和重解析点检查；目标非空检查。
4. **只读理解摘要**：项目目的与当前状态、入口与主流程、原生布局、环境与依赖、启动/构建/测试方式、关键限制或未知项。
5. **复制分类**：按第七节五类逐项列出相对路径或类别、理由、目标位置和验证；选择性复制必须写明纳入与未纳入边界；默认排除必须写明恢复或重建方式；敏感内容只记类别、相对位置和处理，不回显真实值。
6. **目标事实层**：`AGENTS.md`、`CLAUDE.md`、`README.md`、`DEVLOG.md`、`CHANGELOG.md`、`requirements/INDEX.md` 各自已创建、已合并或不适用及其原因，并说明 DEVLOG 工作单元 ID 与状态。
7. **副本验证**：关键文件、启动、构建、测试、源绝对路径残留、敏感内容检查各自的方法或命令、五分类状态和关键结果。
8. **源项目未变证据**：文件与目录清单、文件大小、内容哈希（算法与数量）、特殊条目、适用时的 Git 状态、源目录新增文件检查各自的操作前后值与比较结论；列出不可读取或未哈希范围；mtime 只作辅助信号。结论只能是“源项目未检测到变化”“已检查范围内未检测到变化”或“验证失败”。
9. **失败、限制与遗留项**：失败项、未执行项及原因、环境限制、结果不确定项和后续建议。
10. **授权边界确认**：源项目是否全程只读、目标写入是否未超出授权、是否未擅自复制敏感内容、是否未擅自执行 Git 初始化或 commit、是否未执行网络或远程操作。

`examples/standardized-copy/DELIVERY-REPORT.md` 提供一份简短结构示例。

## 十四、完成条件

只有第一节的全部边界得到遵守、第二节九个阶段全部完成，且第十三节十项报告内容都能如实回答时，才能宣布模式二完成。此外必须成立：

- 源项目未变证据成立，或明确说明只能证明已检查范围；
- 失败、未执行、环境受限和结果不确定项没有被描述为通过；
- 目标保留必要原生结构并建立有实际内容的事实层。

任一条不成立时，报告实际状态与所需决策，不得宣称完成。
