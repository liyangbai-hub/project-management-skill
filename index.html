两个核心观点

不把 AI 当项目数据库，而把 AI 变成读取同一份本地事实、可以互相接力的执行者。

Two core ideas

Do not turn an AI chat into the project database. Let different Agents work from the same durable local facts.

把项目核心规划以及工作事项留在本地文件夹，而不是 AI 的聊天记录

Keep core project plans and work records in the local folder—not in AI chat history

项目目标、状态、计划、决策和验证证据属于项目本身。更换账号、电脑、系统或服务，它们依然存在。

Goals, status, plans, decisions, and validation evidence belong to the project. They survive account, computer, OS, and service changes.

多个 Agent 按照标准化项目规范接力工作，最大化使用多家订阅额度

Standardize multi-Agent handoffs and make the most of multiple AI subscriptions

Claude Code、Codex、其他 Agent 或小伙伴通过统一入口接力，减少反复重建上下文的额度浪费。它不会绕过任何平台条款或配额。

Claude Code, Codex, other Agents, or teammates continue through one shared protocol, reducing quota wasted on repeated context reconstruction. It never bypasses provider terms or limits.

三种模式，一套事实真源

规范的是项目事实和接力方式，不是强迫所有项目采用同一种源码目录。

Three modes, one source of project truth

It standardizes project facts and handoffs—not every framework's source layout.

接力所需的文件，就在项目里

The handoff lives inside the project

<project-root>/
├── AGENTS.md              # 工作协议 / working agreement
├── CLAUDE.md              # Claude Code 入口 / entry pointer
├── README.md              # 当前项目地图 / current project map
├── DEVLOG.md              # 计划、结果、偏差 / plans and results
├── CHANGELOG.md           # 已落地变化 / shipped changes
├── requirements/INDEX.md  # 输入材料状态 / source-material status
└── AUDIT.md               # 证据化审查历史 / audit history

按需创建，不机械堆空文件。文档负责导航；关键行为仍须回到实际代码、配置和命令核验。

Files are created only when meaningful. Documentation navigates; actual code, configuration, and commands still verify behavior.
