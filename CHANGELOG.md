# Changelog

All notable user-visible changes to this project will be documented in this file.

## [Unreleased]

### Added

- Repository portability files, complete Mode 1 examples, and representative macOS validation evidence.
- A single maintenance checklist covering static checks, evaluations, handoff acceptance, cross-platform evidence, and fresh-computer usability.
- A modular formal specification consisting of `SKILL.md` and focused files in `references/`.
- A tool-neutral local project fact layer and multi-Agent handoff protocol.
- A read-only Mode 2 workflow that creates an independently validated standardized copy while preserving the source project.
- An evidence-based Mode 3 review contract with coverage tracking, active disproof, certainty levels, severity, recommendation priority, and authorization boundaries.
- Cross-platform, bilingual installation, and troubleshooting guidance for Claude Code, with conservative Codex compatibility language.

### Changed

- Reworked the Simplified Chinese README with a stronger project message, status badges, earlier installation calls to action, clearer mode presentation, and collapsible FAQs.
- Replaced placeholder clone examples with copyable repository commands, documented current Codex skill locations, and clarified live skill-change detection.
- Git is recommended but optional; the skill no longer initializes repositories or creates commits automatically.
- Native project layouts and toolchains take precedence over a mandatory normalized source directory.
- Development history uses stable work-unit IDs and append-only results while keeping the current-state summary maintainable.

### Removed

- The standalone GitHub Pages landing page, deployment marker, and README navigation entries.
- Maintainer-only publication instructions, related public-documentation references, and publication-specific troubleshooting.
- Every dependency on an external workflow, plugin, or additional skill; the repository is now self-contained.
- Duplicated specification content: one AUDIT record structure, one Mode 2 delivery-report definition, and one place for platform status.
- In-place legacy-project migration, automatic source reorganization, and automatic `[已读]` filename changes.
- Claims that local documentation alone provides complete project understanding or proves runtime behavior.
