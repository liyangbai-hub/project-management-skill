# 跨平台、安装与兼容性参考

本文件是 `project-management` 的正式跨平台参考规范，和 `SKILL.md`、其他 `references/*.md` 一起构成行为真源。安装说明位于 `docs/`，面向人类解释操作；若说明与本文件或技能入口冲突，以正式行为规范为准。

## 1. 可移植性目标

技能的核心交接能力依赖项目目录中的纯文本事实层，而不是作者机器、单一账号或某个聊天会话。任何新电脑、不同 Agent 或不同操作系统都应能够通过文件建立工作上下文。

必须遵守：

- Markdown 和其他文本文件使用 UTF-8；不要依赖本地代码页。
- 仓库文本默认使用 LF 行尾；`.gitattributes` 可声明统一规则。Windows 编辑器若显示 CRLF，不得因此改变文件语义或重复生成整份文件。
- 关键文件名保持精确大小写：`SKILL.md`、`AGENTS.md`、`CLAUDE.md`、`README.md`、`DEVLOG.md`、`CHANGELOG.md`、`AUDIT.md`。
- 新增文件名优先使用 ASCII、小写和连字符；项目自身已有的非 ASCII 文件名不得因本技能被强制改名。
- 核心流程不依赖符号链接、目录联接点或其他重解析点；不能以链接存在作为安装或接力前提。
- 不写入作者机器的绝对路径、用户名、盘符、挂载点或私有环境变量。示例使用 `<repo-root>`、`<project-root>`、`<source-project>`、`<target-project>` 等占位符。
- 核心行为不得要求 Python、Node.js、Bash、PowerShell、Git、GitHub CLI、rsync 或 robocopy。它们只能作为当前平台可用时的便利工具。
- 不假设目录分隔符、大小写敏感性、权限模型或默认 shell；文档中的命令须标明平台并提供不依赖命令的替代步骤。

## 2. 路径与复制安全

模式二创建副本时，先解析源、目标及其已有父路径，再判断相同路径、包含关系、符号链接、Windows 联接点和其他重解析点。不能用字符串前缀代替路径组件比较。

目标必须是源项目之外的独立路径。无法证明隔离时停止。复制工具默认不跟随可能把源外内容带入目标的链接；目标中已有链接若可能把写入回流到源，也必须拒绝或排除并报告。

源项目清单、哈希和其他证据保存于源目录之外。源项目只读规则在 Windows 和 macOS 上相同：不要在源内生成缓存、锁文件、测试输出或报告。目标非空时默认停止，除非用户批准具体冲突策略。

## 3. Claude Code 安装事实

Claude Code 支持个人级和项目级技能目录。当前推荐位置为：

```text
个人级：~/.claude/skills/project-management/
项目级：<project-root>/.claude/skills/project-management/
```

Windows 个人级等价路径示例：

```text
$HOME\.claude\skills\project-management\
```

安装完成后，`SKILL.md` 必须直接位于上述技能目录中：

```text
<skill-directory>/SKILL.md
```

不能出现未预期的额外嵌套，例如：

```text
<skill-directory>/project-management-skill/SKILL.md
```

如果从 Git clone 或 ZIP 得到外层仓库目录，应把仓库内容复制到技能目录，或把技能目录设置为实际包含 `SKILL.md` 的那一层；不要通过猜测路径解决发现问题。

## 4. Codex 兼容边界

`AGENTS.md` 是工具中立的本地工作协议入口，可被 Codex 和其他支持该文件约定的 Agent 使用。Codex Skills 的个人级、项目级发现位置和安装细节可能随版本变化；不在本仓库猜测或硬编码未经官方确认的 Codex 技能路径。

安装 Codex 适配时：

1. 查看当前 OpenAI 官方 Codex Skills 文档中的版本匹配说明和目录规则。
2. 将本仓库内容放到官方文档明确要求的目录，并确认 `SKILL.md` 位于该技能目录根部。
3. 无需复制一套英文执行规范；`AGENTS.md` 继续作为项目接力入口。
4. 若当前 Codex 版本不能自动发现技能，可按官方机制建立薄入口层；不要擅自创建软链接或把 Claude Code 私有路径当作 Codex 路径。

在没有真实 Codex 环境验证前，只能声明“按兼容原则设计”或“待验证”，不得写成完整实测或保证自动发现。

## 5. 测试状态的精确表达

区分以下三类证据：

- **静态兼容分析**：检查文件名、编码、路径写法、依赖声明和文档，不代表运行成功。
- **模拟或约定测试**：在当前系统模拟另一平台的路径、文本或命令约定，不代表另一平台真实行为。
- **真实设备测试**：在该操作系统和目标 Agent 环境执行安装、发现和代表性场景。

本仓库的平台声明必须与实际验证记录一致，且只在一处维护证据：`docs/validation-windows.md` 与 `docs/validation-macos.md`。修改任何平台声明前先读取这两份记录，不在多个文件各写一套状态。

Codex 在没有真实版本验证前不得标记 Fully Tested；应记录版本、发现方式和未验证范围。

## 6. 更新、卸载与残留

更新应先确认安装层级和目标目录，再用新版本内容替换该技能目录；不得把更新操作误作用于项目源目录。若目录非空且包含用户额外文件，先列出冲突并停止，不静默覆盖。

卸载只删除用户明确指定的技能安装目录或其中由本技能创建的文件。不要删除项目中的 `AGENTS.md`、`CLAUDE.md` 或 DEVLOG，除非用户对具体项目路径另行授权；卸载技能不等于删除受管项目事实层。

更新或卸载后检查：

- 目标目录不存在额外嵌套的旧版本；
- 没有遗留临时目录、缓存或下载文件；
- 项目级安装和个人级安装没有被混淆；
- 没有创建 Git、远程仓库或外部发布状态。
